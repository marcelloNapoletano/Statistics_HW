HMWK 1 · From a private key to a public key

A toy version of the maths behind Ethereum keys: a tiny curve you can follow step by step, and an experiment to see how "random" the results look.

The idea in 30 seconds

A private key is just a number k. The public key is a point Q on a curve, obtained by starting from a fixed point G and "adding G to itself" k times: Q = k · G. Adding two points follows a geometric rule: draw a line through them, find where it crosses the curve a third time, then flip that point upside down. Going forward (from k to Q) is easy. Going backward (from Q to k) is believed to be extremely hard on a real curve; this is what keeps the private key secret. Here we use a tiny curve, so that you can follow every step with your own eyes.

📝 What happens at each step

🔁 Why only a few different keys?

G only generates a cycle of a few points. After the last one we come back to the "zero" point ∞ and everything repeats, so keys k and k + (cycle length) give the same public key. A real curve has about 2²⁵⁶ points, so this never happens in practice.

⚡ Why "double-and-add"?

Adding G one time after another needs k steps. Reading k in binary, we can instead double at every bit and add G only at the 1-bits: about log₂k steps. For a 256-bit key that means roughly 380 operations instead of 2²⁵⁶. Try both methods above and compare the number of steps.

🧸 Why is this only a toy?

With so few points, an attacker simply tries every k. On top of that, this particular curve belongs to a weak family (called supersingular) that real systems avoid. The real curve, secp256k1, is huge and not of this type.

💡 Tip: choose a starting point of order 18 (for instance (6, 6)) to see the longest possible cycle on this curve.

The question

Is a public key "random-looking" compared with the private key it comes from? We try many private keys k = 1, 2, 3, …, compute each public key, and look at the results as if they were data. At the same time we run the same tests on a hash function (Keccak-256), which is designed to look random. Comparing the two shows what is special about elliptic-curve keys.
